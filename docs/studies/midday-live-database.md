# Midday live-database study

The original midday brownfield pass was static: PolicyStrata read `packages/db/migrations/*.sql`
and reasoned about the SQL without running it. `docs/brownfield-results.md` recorded that as a
limitation ("No live PostgreSQL comparison was run for any target"). This directory closes it for
midday by loading midday's own `CREATE POLICY` statements into PostgreSQL and asking the database
what a team-scoped principal can actually read.

Run it with:

```bash
uv run python scripts/midday-live-db-evidence.py
```

## Why midday's schema.sql does not load on its own

`../schema.sql` is a byte-for-byte concatenation of 39 committed migrations. Those migrations are
increments on a base schema midday does not keep in `packages/db/migrations` — Supabase manages it
— so loading the concatenation into an empty database produces 188 statements of which most
reference tables, types, roles, and publications that are never created. Two things are therefore
needed: a subset of midday's SQL that is self-contained, and a bridge supplying what Supabase
would.

## Provenance

| File | Provenance | What it is |
| --- | --- | --- |
| `schema_scoped.sql` | **native** | midday's own SQL, copied verbatim. 6 `CREATE TABLE`, 20 `CREATE POLICY`, plus their types, indexes, and `ENABLE ROW LEVEL SECURITY`. Generated by `../scripts/brownfield-midday-live-schema.py`, which selects statements and never rewrites them. |
| `supabase_runtime.sql` | **synthesized** | Raintree-authored. Supabase roles (`anon`, `authenticated`, `service_role`), `auth.uid()`, `private.get_teams_for_authenticated_user()`, the base tables the in-scope tables reference, and a non-owner login role for checks. |
| `seed.sql` | **synthesized** | Raintree-authored. Two teams, one member each, and rows on both sides of every policy. |

The scoped extraction keeps 65 of 188 statements. The 123 dropped statements do not belong to
the six tables with committed policies; the count is printed by the extraction script rather than
left implicit.

## Scope

The frozen migration corpus contains 20 policies across six tables. All 20 are loaded verbatim:

| Table | Policy (midday's name) | Real predicate |
| --- | --- | --- |
| `insights` | Team members can view their insights | `team_id IN (SELECT private.get_teams_for_authenticated_user())` |
| `insights` | Insights can be selected by a member of the team | same |
| `insights` | System can insert insights | `true`, `TO service_role` |
| `insights` | System can update insights | `true`, `TO service_role` |
| `insight_user_status` | Users can view their own insight status | `user_id = auth.uid()` |
| `insight_user_status` | Users can insert their own insight status | `user_id = auth.uid()` |
| `insight_user_status` | Users can update their own insight status | `user_id = auth.uid()` |
| `invoice_recurring` | Invoice recurring can be handled by a member of the team | `team_id IN (SELECT private.get_teams_for_authenticated_user())` |
| `platform_identities` | create/select/update/delete by a member of the team (4 policies) | `team_id IN (SELECT private.get_teams_for_authenticated_user())` |
| `platform_link_tokens` | create/select/update/delete by a member of the team (4 policies) | same |
| `provider_notification_batches` | create/select/update/delete by a member of the team (4 policies) | same |

`insight_user_status` is scoped by user and not by team. It is kept precisely because of that: a
fixture where every table used the same dimension would not catch a checker that assumed one.

## How the principal is bound

PolicyStrata sets `app.tenant_id` per check (`src/policystrata/database.py`). The bridge defines
`auth.uid()` to read it, so passing a *user* UUID as `tenant_id` makes midday's own predicates
resolve that user to their teams. midday's predicate text is never touched.

Checks connect as `midday_app`, a login role that owns nothing and is not a superuser. Both
matter: a table owner or a superuser bypasses row-level security silently, and the fixture would
report safety it never tested.

## Result

| Fixture | Expected gate | Observed gate | Findings |
| --- | --- | --- | --- |
| midday policies intact | pass | pass | 0 |
| one predicate weakened to `USING (true)` | fail | fail | 4, all on `insights` |

The second row is the one that carries the weight. With midday's real predicate on `insights`
replaced by `USING (true)` — the `db_rls_old_ownership_field` drift shape applied to real policy
text — three RLS checks and one state assertion fail, including an unauthenticated read that now
returns rows. `invoice_recurring` and `insight_user_status` stay clean, because their policies
were not touched.

## What this is not

- **Not a midday defect.** midday's committed predicate is correct and the intact run is clean.
  The weakened policy is a synthesized regression, in the same spirit as the cube target's use of
  cube's own intentionally-broken ACL fixtures.
- **Not midday's deployed runtime.** We have never observed it. The bridge is our reconstruction
  of the Supabase surface their policies call, so this is evidence about real *policy text* under
  a reconstructed runtime.
- **Not real data.** Six seeded rows across two synthetic teams.
- **Not Midday's full deployed schema.** This is the full policy set in the frozen migration
  corpus, but Supabase-managed base-schema policies are not committed there and cannot be claimed.
